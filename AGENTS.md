# AGENTS.md - ciliterm

Conventions for AI agents and humans working in this repo.

## What this is

`ciliterm` is a web-first, daily-driver sci-fi terminal (eDEX-UI style).
The terminal is first-class; monitors / globe / on-screen keyboard are optional,
toggleable eye-candy. Web now, Tauri-wrappable later.

## Monorepo layout (pnpm workspace)

- `shared/` - `@ciliterm/shared`. Wire protocol (TS types + zod). **Single source
  of truth** for all client<->server messages. Build with `pnpm --filter @ciliterm/shared build`.
- `server/` - `@ciliterm/server`. Node + TS (run via `tsx`). Express + `ws`.
  Endpoints: `/pty`, `/control`, `/sys`. Native dep: `node-pty`.
- `client/` - `@ciliterm/client`. React + Vite + TS. xterm.js terminal + panels.
- `desktop/` - `@ciliterm/desktop`. Electron shell. Plain JS, CommonJS main
  process. Owns no product logic - it spawns the server and opens a window.

## Protocol rules

- Add/modify messages ONLY in `shared/src/protocol.ts`. Never redefine message
  shapes inline in client or server.
- Every message is a zod `discriminatedUnion` keyed on `t`.
- Server validates inbound with `parseMessage(schema, raw)`; ignore nulls.

## WebSocket endpoints

- `/pty` - one socket per terminal pane. Client sends `attach`/`create` first,
  then `input`/`resize`. Server streams `output`/`cwd`/`exit`.
- `/control` - singleton. Session list (tmux or managed) + SSH host CRUD.
- `/sys` - metrics stream (config-driven interval) + `fs.list`.

## Sessions

- Persistence prefers system `tmux` (`tmux new -A -s <name>`); falls back to an
  in-process long-lived pty + ring buffer. Both expose the same `AttachedSession`
  interface in `server/src/sessions.ts`.

## SSH

- System `ssh` only (key / ssh-agent auth). Host book at
  `~/.config/ciliterm/hosts.json`. **Never store passwords.**

## Spawned shells

- Never hand `process.env` straight to `pty.spawn`. Go through `shellEnv()`
  (`server/src/shell-env.ts`), which strips what the Electron shell injected -
  most importantly `ELECTRON_RUN_AS_NODE`, which would make every Electron app
  launched from a ciliterm terminal boot headless.
- Opening a session must never throw out of the `/pty` handler. One pane failing
  to get a pty is an `{ t: 'error' }` on that socket, not a dead process taking
  every other session with it.

## Desktop shell

- The server is a **child process**, started with
  `spawn(process.execPath, [bundle], { ELECTRON_RUN_AS_NODE: '1' })` - Electron's
  own Node, so there is no second runtime to ship and `node-pty` only has to
  match Electron's ABI.
- `CILITERM_PORT=0`; the real port comes back on stdout behind `READY_PREFIX`.
  That string is a contract between `server/src/config.ts` and
  `desktop/src/main.js` - change both or neither.
- `desktop/runtime/` is generated by `desktop/build.mjs` (esbuild bundle of the
  server + a copy of `client/dist`). Never edit it, never commit it.
- `build.mjs` runs the shared and client builds itself instead of consuming
  whatever `client/dist` holds. Showcase is a **compile-time** flag
  (`import.meta.env.VITE_SHOWCASE`), so a stray `VITE_SHOWCASE=1` in a shell or
  on a CI runner would otherwise ship an installer whose terminal is a
  pre-recorded replay and whose SSH manager is disabled - silently. Keep the
  scrub in place; do not "optimise" the client build back out.
- Packaging config lives in `desktop/electron-builder.yml`, not `package.json`.
  electron-builder validates its schema strictly and rejects unknown keys, so
  there is nowhere to put a `//` comment in JSON, and these options need their
  reasoning attached.
- Native deps are **not** rebuilt for Electron (`npmRebuild: false`). `node-pty`
  is a Node-API addon, so one binary serves both runtimes. Rebuilding would also
  create `build/Release/pty.node`, which node-pty resolves _before_
  `prebuilds/<platform>-<arch>` and which would therefore shadow the correct
  slice of a macOS build.
- The server bundle is **CommonJS**: the dependency graph is CJS and esbuild's
  ESM output cannot `require` node builtins through its shim.
- `asar` is off on purpose. `ELECTRON_RUN_AS_NODE` skips Electron's asar
  patches, so an archived bundle would not load.
- Menu accelerators on Windows/Linux must stay off the `Ctrl` chord space the
  terminal needs (`Ctrl+C/D/R/S/Q/W/Z`). Use `Ctrl+Shift+*` or function keys.
  macOS is exempt - `Cmd` is reserved by the system.

## Panels

- The globe, monitors and on-screen keyboard are eye-candy; the terminal is the
  product. Anything that reaches for hardware the host may not have goes inside
  a `PanelErrorBoundary`. The globe needs a WebGL context, and machines on a
  blocklisted driver, in a VM or behind RDP do not get one - unguarded, that
  throw unmounts the whole app and leaves a blank window with a perfectly
  healthy shell behind it.

## Versions (pinned - do not bump casually)

- `three` 0.171.0, `three-globe` 2.42.4. three.js has frequent breaking
  changes; keep these aligned. Bloom uses `three/examples/jsm/postprocessing`.
- `@xterm/*` 5.5 line.

## Style

- TypeScript strict. ESLint flat config at root (`pnpm lint`), Prettier
  (`pnpm format`). Single quotes, semicolons, width 100.
- No comments that merely narrate code.

## Tests

- `pnpm test` runs Vitest (`vitest.config.ts`, node env, `tests/**/*.test.ts`).
- Tests import pure modules directly; keep unit-testable logic dependency-light
  (e.g. `server/src/net-util.ts`, `server/src/ssh-cmd.ts`) rather than tangled
  with `node-pty` / `systeminformation` / config side effects.

## Run

- Dev: `pnpm dev` (builds shared, then runs server + vite with WS proxy).
- Prod: `pnpm build` then `pnpm start` (Express serves `client/dist`).
- Auth: WS `?token=` is auto-off on loopback binds and auto-on for non-loopback
  hosts (or when `CILITERM_TOKEN` is set); `CILITERM_NO_AUTH=1` force-disables.
  See `AUTH_DISABLED` in `server/config.ts`; the client captures the token from
  the launch URL in `transport/auth.ts`.
- three/three-globe are code-split: the Globe is `React.lazy`-loaded and `three`
  + `xterm` are separate Vite manualChunks, keeping the initial bundle small.
